# 导出内容复制到剪贴板设计

## 背景

当前本人记录导出和管理员任务数据导出已经由服务端以内联 `content_base64` 返回文本内容，但小程序端会把内容写入本地文件，并在部分路径中把文件路径复制到剪贴板。移动端用户拿到文件路径无法直接使用。

## 目标

- 本人记录导出后，剪贴板中直接得到可粘贴文本。
- 管理员任务数据导出后，剪贴板中直接得到可粘贴表格文本。
- 导出文本包含打卡日期、打卡任务名称、打卡内容名称、打卡心得。
- 保留现有登录、资料完整性、成员/管理员权限校验。

## 方案

服务端继续返回 `content_base64`，避免变更接口形状。小程序端拿到 `content_base64` 后解码为 UTF-8 文本，调用 `wx.setClipboardData` 复制正文，不再写入文件，也不再复制 `wx.env.USER_DATA_PATH` 下的文件路径。

本人记录导出继续使用 Markdown 文本，每条记录写明：

- 打卡日期
- 打卡任务名称
- 打卡内容名称
- 打卡心得

管理员导出继续使用 TSV 文本，方便粘贴到表格工具。表头调整为任务、成员、打卡内容、打卡日期、打卡心得。

## 错误处理

- `content_base64` 为空时提示导出内容为空。
- 解码或复制失败时提示导出失败。
- 无记录、非成员、非管理员等业务错误沿用服务端现有响应。

## 验证

- 小程序页面测试断言本人导出和管理员导出调用 `wx.setClipboardData`，复制内容正文而不是文件路径。
- 服务端 smoke test 断言导出正文包含任务名称、内容名称、日期字段和心得。
- 运行 `node --check`、页面测试和小程序静态检查。
