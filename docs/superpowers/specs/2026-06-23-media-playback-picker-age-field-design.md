# 媒体播放、文件选择文案与年龄输入调整设计

## 目标

完成以下三项修改：

1. 修复管理员发布后音频或视频无法播放的问题。
2. 将音频、视频文件选择弹窗中的选项统一显示为“从微信聊天中选择”。
3. 仅删除加入任务页的年龄输入框；后端年龄字段、数据库字段、既有数据以及协议和隐私政策保持不变。

## 根因

微信聊天文件选择器会同时返回临时路径和原始文件名。当前上传链路只把临时路径交给 `wx.uploadFile`，没有把原始文件名传给服务端。部分微信临时路径没有扩展名，上传请求也可能将媒体标记为 `application/octet-stream`。服务端据此生成无扩展名对象并保存通用 MIME 类型，微信音视频播放器因无法可靠识别媒体格式而拒绝播放。

本地历史上传目录中存在多批无扩展名媒体文件，与该数据流一致。

## 方案

### 媒体上传与播放

- 文件选择结果保留原始文件名。
- 客户端上传时通过表单字段一并提交原始文件名。
- 服务端只取原始文件名的 basename，避免路径注入。
- 服务端根据可信扩展名补全音视频 MIME 类型；请求已提供明确音视频 MIME 类型时保持原值。
- 存储对象使用带扩展名的名称，并写入可被播放器识别的 `Content-Type`。
- 任务发布和详情读取仍保存、使用现有 `media_url`，不改变业务接口结构。
- 本次修复保证新上传媒体可播放；不迁移历史无扩展名对象。

### 文件选择弹窗

- 音频弹窗保留一个选项，文字为“从微信聊天中选择”。
- 视频弹窗也只保留一个选项，文字为“从微信聊天中选择”。
- 两种媒体都使用 `wx.chooseMessageFile`，并按允许的扩展名筛选。
- 取消选择时不提示错误；其他选择失败继续显示现有错误提示。

### 年龄输入

- 从 `pages/join/join.wxml` 删除年龄输入框。
- 从页面 data 和提交方法中移除 `age` 的读取及传递。
- 服务端 `/api/tasks/join` 保留年龄兼容逻辑，未收到年龄时继续使用默认值 `0`。
- 不修改协议、隐私政策、数据库结构或历史成员数据。

## 测试

- 客户端上传测试：验证上传请求携带原始文件名。
- 任务页测试：验证音频和视频弹窗均只展示“从微信聊天中选择”，并调用正确的聊天文件选择逻辑。
- 服务端测试：验证无后缀临时路径配合原始 `.mp3`/`.mp4` 文件名时，最终存储键和 MIME 类型正确。
- 加入页测试：验证 WXML 不再包含年龄输入框，提交载荷不包含 `age`。
- 运行现有 Node 测试、项目静态检查和服务端相关测试，确认无回归。

## 边界与兼容性

- 不修改现有登录资料弹窗，因为其中没有年龄字段。
- 不处理历史已上传且缺少扩展名的媒体；如需修复历史任务，应另行设计对象迁移和数据库 URL 更新。
- 不引入音视频转码。用户仍需选择微信播放器支持的媒体编码格式。
